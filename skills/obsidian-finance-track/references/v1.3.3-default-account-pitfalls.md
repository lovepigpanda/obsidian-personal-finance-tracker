## Pitfall 1: `aweskill install` 不复制 `scripts/` 也不复制 `config/`

**症状**: 跑 `aweskill install . --override --all` 之后, `~/.aweskill/skills/obsidian-finance-track/` 里有 `SKILL.md` / `SKILL_en.md` / `references/`,但**没有 `scripts/` 也没有 `config/`**。`transaction_create.py` import `lib.parsers` 直接 ModuleNotFoundError。

**根因**: `aweskill install` 只复制 `skills/<skill-name>/` 子树, 仓库根的 `scripts/` / `config/` 是项目级文件, 不在技能包里。

**V1.3.4 修复** (用 `install.sh` 一键): 见 `templates/install.sh` (跟仓库根 `install.sh` MD5 一致)
```bash
# 直接 cp 模板 + 跑
cp ~/.hermes/skills/productivity/obsidian-finance-track/templates/install.sh ~/
bash ~/install.sh --dry-run     # 验证
bash ~/install.sh                # 真跑
```

**手动修复** (仍适用, 当 `install.sh` 不够用时):
```bash
# 1. aweskill 同步技能层
aweskill install . --override --all

# 2. 手动复制仓库根的 scripts/ + config/ 到 central store
rm -rf ~/.aweskill/skills/obsidian-finance-track/scripts
cp -r scripts ~/.aweskill/skills/obsidian-finance-track/scripts
mkdir -p ~/.aweskill/skills/obsidian-finance-track/config
cp config/default_accounts.yaml ~/.aweskill/skills/obsidian-finance-track/config/

# 3. 同步到 Hermes (注意 path 是 skills/<category>/, 不是 skills/)
rm -rf ~/.hermes/skills/productivity/obsidian-finance-track
cp -r ~/.aweskill/skills/obsidian-finance-track ~/.hermes/skills/productivity/obsidian-finance-track

# 4. 验证 MD5 三处一致 (仓库 / central / Hermes)
```

**关联**: `aweskill-correct-commands` skill 已有同主题内容, 但 V1.3.3 加 `config/` 后必须重新走一遍。

## Pitfall 2: `config/default_accounts.yaml` 必须同时存在于仓库和 vault

**症状**: 用户 onboarding 后, `transaction_create.py` 启动 resolver, config 路径找不到, 全走 `fallback` (Alipay 兜底)。`"地铁 8 块"` 应该是 `交通卡` (e-wallet, 余额 10 块), 实际写到 `Alipay` (余额 0 块), 当月余额汇总偏 8 块。

**V1.3.4 修复** (用 `install.sh` 一步到位): `bash install.sh` 必跑, 第 6 段是 `cp config/default_accounts.yaml ~/Obsidian/finance/`。**不再依赖 Onboarding 步骤 3 手动 cp**。

**为什么不放 `~/Obsidian/finance/config/`?**
- vault 目录结构是 `Templates/` `Categories/` `Dashboards/` `Accounts/` `Transactions/` (无 `config/`)
- 放 vault 根是最小改动, 跟 `account-list.md` 同级
- 如果想严格按 vault 子目录, 先 cp 到 vault 根, 后续用户愿意再 move 进 `config/`

## Pitfall 3: transfer 类型只创建 out 不创建 out+in 配对 (V1.3.3 已知 bug, V1.3.4 ✅ FIXED)

**症状**: 用户说"从支付宝转 5000 到招行, 还信用卡", agent 跑 `transaction_create.py --type transfer --account Alipay --to-account CMB`, 脚本**只创建 `Transactions/transfers/out/...md` 一个文件**, 没有 `Transactions/transfers/in/...md`。
- 后果 1: `daily_integrity_check.py` 第 1 步"transfer 配对完整性" 立刻报错 (孤立 out)
- 后果 2: 用户 CMB 余额不变, 但 Alipay 减了 5000, 整个资产负债表歪了
- 后果 3: AGENTS.md 强调的 T4 "必须创建 2 个文件" 被破坏

**根因** (V1.3.3 我自己 ship 的 bug): `transaction_create.py` 的 `create_transaction()` 函数, transfer 分支只走一个路径 (out), 没有循环创建 in。**端到端测试时只跑了 expense 没跑 transfer, 没暴露**。

**V1.3.4 修复** ✅:
- `create_transaction()` 检测 `type=transfer` 时, 生成 `transfer_pair_id` (`T-{date}-{md5[:8]}`), **同时**创建 out + in 两个文件, 共享 pair_id
- out 文件: `account=from, to_account=to, type=transfer-out`
- in 文件: `account=to, to_account=from, type=transfer-in` (注: 镜像, 表达"同一笔")
- 同名文件检测覆盖双文件: out 或 in 任一存在都返回 `type="ask"` 软告警
- 错误返回加 `type` 字段 (`"ask"` vs `"error"`) — 详见 `references/v1.3.4-fixes-and-pitfalls.md` 修复 2
- 用户 `--account` 拼写错时, `type="error"` 不再 silent fallback — 详见同 reference 修复 3
- 端到端 7/7 PASS (T1-T7), 详见 `references/v1.3.4-fixes-and-pitfalls.md` 修复 1

**临时 workaround** (V1.3.3, V1.3.4 之前用): agent 检测到 transfer 输入时, **不要** 用 `transaction_create.py --type transfer`, 改用 `expense` (from_account 扣款) + `income` (to_account 入账) 两个独立调用。**V1.3.4+ 不再需要此 workaround**。

## Pitfall 4: learning.json 在 `~/.obsidian-finance/`, 跟 vault 不在一起

**症状**: 用户 onboarding 后, 第一次记账, learning.json 自动创建在 `~/.obsidian-finance/learning.json`。**用户从来不知道有这文件**。第二次冲突时 `ask_message` 弹出, 用户问"这个问我是从哪学来的?", agent 也答不上 — 因为文件不在 vault 里, agent 看不到。

**修复**: 学习机制是 agent 的内部状态 (类似 Hermes session memory), 不应该跟 vault 账本混在一起。但**给用户一个 `--show-learning` 命令查看 learning.json 内容**会更透明 (V1.3.4 待加, V1.3.5 必做)。

## Pitfall 5: resolver 的 5 层优先级中, note 隐式 > config 规则 (不是反过来)

**症状**: config rule 写 `"地铁|公交" → 交通卡`, 用户说"用支付宝买了地铁票 8 块", note 包含 "支付宝" 和 "地铁"。**resolver 走 note 隐式分支, 直接用 "Alipay"**, config rule 没机会跑。**但用户的真实意图可能是"地铁票是预定的, 默认交通卡; 但这次用支付宝临时买, 是 Alipay"。**

**判断**: 这是设计 trade-off, 不是 bug:
- **note 隐式优先** 反映"用户说 XX 就是 XX", 更尊重用户输入
- **config 优先** 反映"系统规则最高", 但容易把"偶尔例外" 错当成"长期默认"
- **当前实现选 note 优先**, 因为"用户提了具体账户" > "系统默认"

**改进** (V1.3.4 可选): 加 `--prefer-config` 标志, 让用户/agent 选择优先级。但**默认 note 优先, 不要改**, 除非用户明确反馈。
